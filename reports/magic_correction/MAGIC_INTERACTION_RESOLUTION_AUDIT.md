# Phase 4 — Magic Interaction & Prompt Resolution Audit

## 1. Root Causes Resolved

1. **Async Promise Deadlock in Session Manager**:
   - Previously, `BattleSessionManager.submitPlayerAction()` awaited `game.playCard()`, which awaited `InteractionController.request()`, creating an unresolved Promise that hung HTTP `POST /api/sessions/:matchId/action` indefinitely whenever a Magic card required a player prompt.
   - **Fix**: Added `suspendOnRequest` (`suspendOnInteraction: true`) + `InteractionSuspendedError` in `engine/interaction.js` and caught it in `AsyncResolver.resolveAbility()` (`engine/resolver.js`), persisting a serializable `pendingExecution` record in `state.pendingExecutions` and returning `{ success: true, suspended: true, status: 'AWAITING_INTERACTION', interactionId, interaction }`.
2. **Broken Post-Restore Continuation**:
   - Previously, `InteractionController.respond()` resolved `pendingResolvers` in memory only, so after SQLite serialization/deserialization (`restoreMatch()`), responding to a prompt left the Magic effect unexecuted.
   - **Fix**: Implemented `game.resumeExecution(interactionId, validatedResponse)` in `engine/index.js` + `replayQueue` in `AsyncResolver.resolveAbility()`, resuming at the exact suspended `phase` (`MAIN_CLAUSES` / `FOLLOW_UP_CLAUSES`), `clauseIndex`, and `priorResponses` even across full DB eviction and restoration.
3. **`ReferenceError: findMatchingCandidate is not defined` in `engine/selectors.js`**:
   - Discovered during Phase 8 testing (`MAGIC-F01`, `MAGIC-GHI01`, `MAGIC-JK01`): `findMatchingCandidate` was nested inside `validateSelection()` (line 624), causing `executeTargeting()` (line 1054) and `resolveTargets()` (line 1315) to throw `ReferenceError` whenever a targeted effect resumed from a player selection!
   - **Fix**: Hoisted `findMatchingCandidate` to module scope in `engine/selectors.js`.
4. **Candidate Pool Validation Mismatch in `engine/session_manager.js`**:
   - Previously, `submitPlayerAction` only checked `c.candidateId || c.id`, rejecting valid `stackId` / `cardId` selections generated by `selectors.js`.
   - **Fix**: Normalized candidate ID extraction across `candidateId`, `id`, `stackId`, `cardId`, `stack.id`, and `card.id`.
5. **Browser UI Prompt Disconnection (`battle_arena.js`)**:
   - Added `renderEngineInteractionPrompt()` and `submitEngineInteractionResponse()` in `battle_arena.js` to render engine-generated `pendingInteractions` and submit `INTERACTION_RESPONSE` back to `/api/sessions/:matchId/action`.
